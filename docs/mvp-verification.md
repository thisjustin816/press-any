# MVP device regression checklist

The owner accepted the working MVP on 2026-10-06. Keep these physical-iPhone checks as the
regression record; they no longer block v1 work.
Do not commit commercial ROMs, saves, or other copyrighted test content.

## On a physical iPhone

Automated coverage runs in CI (`docs/ci.md`). These checks need a real device.

The `Shared ROM and patch UI flows` CI job automates the share-sheet, queue and return-to-details
scenarios on a simulator. Keep these device checks pending until they pass on an iPhone.

Verify with a user-supplied legal ROM:

- [ ] Generate/open the iOS project from a clean checkout.
- [ ] A fresh install opens on the welcome screen, in Light and Dark Mode and at the largest text size; Get Started or a swipe down leaves the library, and later launches skip it. Settings > How Press Any Works shows it again.
- [ ] Launch a GB game and a GBC game through SameBoy with correct colors, orientation, native speed and audio.
- [ ] Touch input works with acceptable latency.
- [ ] With Game Boy selected and Controller Theme set to Classic, slide a thumb around the D-pad in portrait and both landscape orientations: cardinals stay clean, diagonals engage only near the corners, and sliding back to a cardinal or the center releases the diagonal without lifting.
- [ ] With Playtiles selected and the physical overlay aligned, press left/right/up/down slightly off-center: each stays straight. Deliberate diagonals and sliding back to straight directions still work.
- [ ] From Files and a browser's downloaded-file share sheet, open `.gb`, `.gbc`, `.ips` and `.bps` in the app (use More if needed). ROMs offer Quick Play or Import Review; patches require a Game and base Build. Cancelling leaves the sender's file and library unchanged. While gameplay is open, the shared file waits until the game and its session sheet close.
- [ ] With a Bluetooth controller, the D-pad and left thumbstick both move in all eight directions; slight stick drift does nothing. The controller's A and B are Game Boy A and B, Menu or X is START, Options or Y is SELECT, and the shoulders do nothing. On a PlayStation controller, Circle is A, Cross is B, Triangle is START and Square is SELECT. Disconnect while holding a direction: no button sticks, the touch controls return and the game pauses with a notice. Repeat with a paused game: it stays paused.
- [ ] In iOS Settings > General > Game Controller, change a global button mapping and invert the left stick's vertical axis: the game follows both. Add a customization specifically for Press Any and verify it applies only here. Restore the default mapping after the check.
- [ ] Cartridge rumble routes correctly to controller/phone where supported.
- [ ] Backgrounding pauses emulation, flushes battery save, and writes lifecycle autosave.
- [ ] Foreground autoresume honors Always / Ask / Never behavior.
- [ ] Add a modified ROM as a second Build; Game identity remains stable.
- [ ] Import a known No-Intro regional release, then search by another title in its family: "Pocket Monsters Crystal" finds Pokémon Crystal. Rename Game in Game Details, reopen the app, and verify the new title and the former-title search both work.
- [ ] In Settings > Library > Regions and Languages, verify USA, Europe, Japan is the initial region order and reorder both lists. Import Japan then USA releases of one family: review proposes the better title and Preferred mark. Cancel changes nothing; decline either proposal and Import keeps that choice; accept both and reopen the app to verify them. A lower-ranked release doesn't take Preferred, ties stay stable, and a title set with Rename Game never receives a replacement proposal. Changing the order alone leaves existing Games unchanged.
- [ ] Keep a protected Japan-titled Game holding a USA release under the default order: import never proposes replacing its title. Library view menu > Suggest Names shows its current title, proposed USA title and release region above Build names; homebrew and Games already titled by their best release get no Game suggestion. Cancel changes nothing. Accept one title, edit another and skip a third, then Rename and relaunch: accepted titles keep the old title as an alias and allow later regional import proposals, edited titles stay protected, skipped Games stay unchanged, and every Preferred Build stays put. Existing Build name suggestions still accept, edit and skip as before. With neither kind to suggest, the empty state says Game titles and Build names look right.
- [ ] Keep regional releases of one family in separate Games. Library view menu > Suggest Game Merges lists them. Close the review and verify nothing changed; reopen, choose a subset, survivor and title, and Merge. Reopen the app: selected Builds keep their identities, lineage, states and Save Profiles, the survivor keeps its artwork or receives available source artwork, and unselected Games stay separate. A group with duplicate images refuses the move before any Game is merged.
- [ ] Import an unknown ROM and choose Match Game. Search the library and No-Intro data, including a base ROM absent from the library, and mark it as a hack or another Build. Before Import, the library is unchanged; after Import and relaunch, the recorded base game remains visible and verification stays Unknown. Import the base later: review offers the Game and Base mark; cancel or decline leaves them alone, and confirming links the clean Base without replacing the hack's lineage. With several Games recording that base, choose the destination explicitly.
- [ ] Import a ROM with metadata tags, such as `Example (Europe) (En,Fr) (Rev A) [v1.10].gb`. Correct or clear Build Details in review. Reopen the app and confirm Technical Info shows the chosen values.
- [ ] Quick Play that ROM, then Add to Library. Build Details uses the picked filename's metadata.
- [ ] Share a compatible Save Profile between Builds, then fork it and confirm divergence.
- [ ] State created on Build A is never loadable on Build B.
- [ ] Create an IPS/BPS-derived Build and launch it.
- [ ] Keep Game Details open, share a patch to the app, apply it to that Game and return to details. The new Build appears without backing out and reopening the Game.

- [ ] Remove its generated-ROM cache, relaunch, and confirm deterministic rebuild.
- [ ] Quick Play a new test build using a copy of Main; mutate the temporary save; Main remains unchanged.
- [ ] Promote the Quick Play session and choose whether its save becomes a new/default profile.
- [ ] Quick Play an 8 MB image on device and record the time from choosing the file to the first frame, which the game screen shows as "First frame in N ms"; it opens on the game, not the boot logo, and nothing optional (shaders, skins, custom layouts, detection) loads before it. Then play for a minute and confirm normal speed and audio.
- [ ] On both controller layouts and in both themes, the Press Any wordmark looks like a raised button. Tapping it freezes the game and opens the menu with Resume; dismissing the menu leaves the game frozen until Resume. The button remains available with a physical controller. Game-picture taps open the same paused menu only when Settings > Tap Game for Menu is on. Dragging a thumb across either doesn't open it. The first game played shows "Tap Press Any for the menu." once, and never again.
- [ ] On an iPhone with a Dynamic Island and one without, rotate a library game and Quick Play into both landscape orientations, then back to portrait, while running and while paused. The GBA controls and picture clear the safe areas; Integer keeps whole pixels and Fill uses the available picture area. Hold a touch control while rotating: it releases, and Resume stays centered on the picture when paused. START and SELECT are small round buttons right of the D-pad's center and below it, START above SELECT, each with its slanted name plate to its left, and the menu button is below the picture.
- [ ] With rotation lock on, gameplay keeps the locked orientation; with it off, it follows the phone. Close a game in landscape: the library returns to portrait. Settings and a file shared over the game open in portrait. Choose Playtiles with no controller connected: gameplay stays portrait even when the phone turns sideways. Set Orientation to Landscape: a game launched with the phone upright turns sideways at once and follows the phone between the two landscape directions only. Set it to Portrait: the game stays portrait when the phone turns. Change it from the game menu's Settings: it applies when the sheet closes.
- [ ] Connect a controller in landscape: touch controls hide, the menu and paused Resume remain usable, touching reveals the controls, and the controller's next button press hides them again. Disconnecting releases held input and pauses the game.
- [ ] With Playtiles chosen, connect a controller: the layout becomes Game Boy and follows Orientation (Automatic, Portrait and Landscape). Repeat with a controller connected before launch, in a library game and Quick Play, and with Hide Touch Controls with a Controller off. Change the chosen layout in the game's Settings while connected: Game Boy stays active. Disconnect: the game pauses and the chosen layout returns without a restart; Playtiles returns to portrait. Settings, shared-file sheets and the library stay portrait throughout.
- [ ] Screen Scaling: Integer shows every Game Boy pixel the same size on both layouts; Fill makes the picture larger, most visibly on Playtiles and on Pro Max phones, with even, sharp pixels and no shimmer while scrolling.
- [ ] A Game Boy game starts green. In its Settings sheet, Screen Colors offers the four Game Boy choices and a Game Boy Color game's offers the six correction choices, never both; App Settings shows neither. Switch through them: the picture changes behind the sheet while the game stays paused. Reset and load a state; the chosen colors remain. Check that a System choice inherits through Game and Build, and that a Build override wins.
- [ ] The game menu's Sound shows the current choice. Pick Always Off and the game goes quiet while music from another app keeps playing; pick Always On with the phone set to silent and the game plays. Close the game and open another: it uses the last choice, and App Settings shows it.
- [ ] Settings > Acknowledgements lists SameBoy, GRDB.swift and gbtoolsid, and each opens its license text or credit.
- [ ] Controller Theme: Classic shows dark status bar text and Dark light text, and Match System follows Light and Dark Mode. The library behind the game keeps its own appearance.
- [ ] A library game shows the boot logo by default; with Settings > Skip Boot Logo on, it opens on the game.
- [ ] Move a Build to its own Game and merge it back; Build identity and data remain intact.
- [ ] Make Separate Game shows a review with the Build's own Save Profiles and the artwork selected; the new Game gets copies, shows Split From, and the original Game is unchanged.
- [ ] In Import Review for a new Game, choose artwork from Photos, then replace it from Files: the preview changes, and after Import the library tile and the Game show it. Choose a file that isn't an image: review refuses it and the import still works. Add a Build to a Game that has artwork without choosing any: its artwork stays.
- [ ] Import a homebrew ROM (GB Studio, GBDK or RGBDS); Import Review and the Build's Technical Info show what it was made with.
- [ ] Import a second build of a homebrew game whose filename differs from the first, such as "Game-v5-Stability.gbc"; Import Review suggests adding it to the first Game and reads version 5, status Stability.
- [ ] Play Build A of a homebrew Game, then launch Build B, made with different tools, with the same save; the warning appears, and Play with a Copy leaves the original save unchanged.
- [ ] Replace Save from File on a profile with a save asks first and keeps "<name> before import"; on a blank profile it doesn't ask.
- [ ] Load State shows each state's thumbnail.
- [ ] A profile's Badge takes one emoji, shows it beside the name in the profile list and the Play with Save and Default Save menus, and refuses text.
- [ ] Deleting a profile asks first, naming it; a Build that played it plays the Game's default afterwards.
- [ ] Delete a base Build that has a patched Build: the confirmation names the patched Build, and both leave the Game. Settings > Recently Deleted lists it with the days left; Restore brings both back with their save states. Delete Game from a Game's menu, relaunch, and restore it from Recently Deleted with its Builds and saves. Delete Now removes an item for good.
- [ ] A Save Profile's Save States lists its states with their pictures, Builds and dates. Rename one and Load State shows the new name; clear the name and it reads "Save State" again. Delete one, then restore it from Recently Deleted. Delete its profile too: restoring the state asks for the profile first.
- [ ] The library list labels a Game Boy Color game "Game Boy Color".
- [ ] Settings > Check Library Files reports an intact library.
- [ ] On a development build with a disposable Save Profile, save in the game and force-quit. In Xcode's Devices and Simulators, Download Container and keep an untouched copy. Change one byte of that profile's `battery.sav` under `Library/Application Support/AppData/UserData/SaveProfiles`, leaving the database unchanged, then Replace Container. Launching with that profile stops and offers Use It Anyway, Start a New Save and Cancel; after Cancel, downloading the container again confirms the altered file was kept unchanged. Launch again and choose Use It Anyway: a profile named "<name> before playing" appears and the game starts. Restore the untouched container before continuing.
- [ ] With an intact battery save and an Auto State, force-quit and use the same container workflow to change one byte of the Auto State's `.state` file under `Library/Application Support/AppData/UserData/States`, leaving the database unchanged. With Resume Games set to Always, launch the game: it boots from the battery save, says the resume point was kept, and the altered state remains unchanged. Restore the untouched container after the check.
- [ ] Play for five minutes with speaker sound, then with Bluetooth headphones: no crackle, the sound keeps up with the picture, and switching between them keeps the sound. With Low Power Mode on, any gap is short and doesn't keep recurring.
- [ ] With a controller connected the touch controls hide; touching the screen shows them, and the controller's next button press hides them again. With Settings > Hide Touch Controls with a Controller off, they stay shown.
- [ ] Touch Haptics: Light by default, Medium is stronger, Off has none, and there are none while a controller hides the touch controls.
- [ ] Save in a game with a battery save, wait 10 seconds, then force-quit from the app switcher: relaunching keeps the in-game save.
- [ ] Save a state, then save in the game, then load the state: it asks first, and Load keeps the newer save as "<profile> before loading state".
- [ ] In Quick Play the game menu shows Save State grayed with "Add to Library to save states", and Add to Library… opens the promotion review.
- [ ] Settings > Systems > Game Boy Color opens settings that apply to every Game Boy Color game without its own.
- [ ] Save in a game, then within a few seconds load a state taken before that save: it asks first, Cancel changes nothing, and Load keeps the newer save as "<profile> before loading state".
- [ ] Quick Play a game with no battery save, play past the title screen, and Add to Library with a new profile: Play on the new Build resumes there.
- [ ] Quick Play a ROM already in the library with a copy of its save, play, and Add to Library with a new profile: Play on that Build continues the Quick Play progress, and the Game's other Builds keep their saves.
- [ ] A patch that turns a Game Boy game into a Game Boy Color one makes a Game Boy Color Build that boots in color, and still does after Remove Generated ROM.
- [ ] Pull down Control Center and Notification Center mid-game: the game stops, and picks up again when they close. With a button held when they open, nothing stays pressed. Lock and unlock, and switch apps, with Resume Games set to Always, Ask and Never in turn. A game paused from the menu stays paused through all of these.
- [ ] At the largest accessibility text size, the library shows one column with full titles, and a Game's Builds, saves and Technical Info hashes stay readable.
- [ ] In a game, Fast Forward from the game menu runs at the Fast Forward Speed setting: change it between 1.5×, 4× and Unlimited in the game menu's Settings while Fast Forward is on, and the speed follows at once. A Game's own setting overrides App Settings.
- [ ] Fast Forward Audio Muted is silent while Fast Forward runs, and the sound returns at normal speed with no burst of old sound. Accelerated plays the sound sped up with the game at 2× and 4×, and stays muted at 8× and Unlimited.
- [ ] On both layouts, in Classic and Dark, the D-pad, A, B, SELECT and START look raised like the menu button, lit along their top edges. A, B, SELECT and START sink when pressed; the Game Boy D-pad tips instead, its held arm shading toward the end with no hard edge, diagonals included. On Playtiles the alignment guide also looks raised, lit along its top edge with a shadow below. Pausing from the menu shows Resume centered on the game picture on both layouts, clear of the guide and controls.
- [ ] A game without artwork shows its placeholder cartridge filling most of the library tile and sitting cleanly in the list row's thumbnail, in both themes.
- [ ] Files shows a Press Any folder under On My iPhone. Export ROM on a Build and Export Save on a profile with a save each add a file to Press Any › Exports, a patched Build's ROM matches its Technical Info hash, and exporting again adds a numbered copy. Opening a ROM from that folder still offers Quick Play or Import.
