# MVP device regression checklist

The owner accepted the working MVP on 2026-10-06. Keep these physical-iPhone checks as the
regression record; they no longer block v1 work.
Do not commit commercial ROMs, saves, or other copyrighted test content.

## On a physical iPhone

Automated coverage runs in CI (`docs/ci.md`). These checks need a real device.

The `Shared ROM and patch UI flows` CI job automates the share-sheet, queue and return-to-details
scenarios on a simulator. Keep these device checks pending until they pass on an iPhone.

The notes and favorites app tests cover editing, canceling, clearing, relaunching, both favorite
actions, and combining Favorites Only with search. Core tests cover the populated v9 upgrade,
repository round-trips, lifecycle playtime and move/copy behavior. The checks below still need
an iPhone.

Verify with a user-supplied legal ROM:

- [ ] Generate/open the iOS project from a clean checkout.
- [ ] A fresh install opens on the welcome screen, in Light and Dark Mode and at the largest text size; Get Started or a swipe down leaves the library, and later launches skip it. Settings > How Press Any Works shows it again.
- [ ] Launch a GB game and a GBC game through SameBoy with correct colors, orientation, native speed and audio.
- [ ] Touch input works with acceptable latency.
- [ ] With Game Boy selected and Controller Theme set to Classic, slide a thumb around the D-pad in portrait and both landscape orientations: cardinals stay clean, diagonals engage only near the corners, and sliding back to a cardinal or the center releases the diagonal without lifting.
- [ ] With Playtiles selected and the physical overlay aligned, press left/right/up/down slightly off-center: each stays straight. Deliberate diagonals and sliding back to straight directions still work.
- [ ] From Files and a browser's downloaded-file share sheet, open `.gb`, `.gbc`, `.ips` and `.bps` in the app (use More if needed). ROMs offer Quick Play or Import Review; patches require a Game and base Build. Cancelling leaves the sender's file and library unchanged. While gameplay is open, the shared file waits until the game and its session sheet close.
- [ ] Install this build alongside another emulator (Manic EMU or Delta). Tap a legal `.gb` in Files and record which app opens, then use Share > Press Any (More if needed). Confirm Quick Play and Import Review both work, and cancellation preserves the source. Repeat sharing with `.gbc`, `.ips` and `.bps`; patches ask for a Game and base Build. Record the iPhone/iOS version, both app versions and each result below. With two claiming apps the default is iOS's choice; Owner rank is not a guarantee.
- [ ] In Files, share a downloaded hack's `.zip` (a `.bps` with a readme) and confirm Press Any is offered (More if needed): its patch opens Open Patch with the base preselected and the readme is skipped. Share a `.sav` and an `.srm` and confirm each opens Open Save. Tapping a `.zip` in Files still opens it where it did before.
- [ ] With a Bluetooth controller, the D-pad and left thumbstick both move in all eight directions; slight stick drift does nothing. The controller's A and B are Game Boy A and B, X is START, Options or Y is SELECT, and the shoulders do nothing. On a PlayStation controller, Circle is A, Cross is B, Triangle is START and Square is SELECT. With touch controls hidden, press Menu: the game menu opens without pressing START. Press Menu again: it closes and resumes. Hold Menu and press another button: the menu does not toggle again until Menu is released and pressed. Repeat after opening the menu by touch. Disconnect while holding a direction: no button sticks, the touch controls return and the game pauses with a notice. Repeat with a paused game: it stays paused.
- [ ] In iOS Settings > General > Game Controller, change a global button mapping and invert the left stick's vertical axis: the game follows both. Add a customization specifically for Press Any and verify it applies only here. Restore the default mapping after the check.
- [ ] Cartridge rumble routes correctly to controller/phone where supported.
- [ ] Backgrounding pauses emulation, flushes battery save, and writes lifecycle autosave.
- [ ] Play a disposable library Build for more than two minutes. Its Save States screen and the game menu's States show no crash checkpoint. Download the container and check that only one `crashRecovery` state exists for its Build and Save Profile, with its timestamp refreshed; no migration is required. A successful Auto State or clean close removes it.
- [ ] On a Debug build, play a library game for at least a minute and choose Crash App (Debug) from the game menu. Relaunch: the library offers Recover Session and Start Normally without opening a game. Recover Session returns to the checkpoint. Crash again during recovery or play: the next launch offers the choice again and never loops into gameplay. Confirm the crash menu item is absent in Release.
- [ ] Repeat the crash and choose Start Normally: the library opens. Download the container to confirm the checkpoint remains. Relaunch: no game opens automatically. Start that Build again, including with another Save Profile: its old checkpoint is removed. A crash in Quick Play offers no recovery.
- [ ] Play a library game, send the app to the background and let iOS end it after its Auto State is written (use Xcode to terminate the suspended process if needed; do not use a crash during play for this check). Relaunch with Resume Games set to Always, Ask and Never in turn: that game reopens and its Auto State is restored, offered or ignored respectively. A game closed with Close Game does not reopen.
- [ ] Foreground autoresume honors Always / Ask / Never behavior.
- [ ] Add a modified ROM as a second Build; Game identity remains stable.
- [ ] Import two builds of one homebrew project with different filenames. The second preselects the project's Game and shows its evidence below the destination. Cancel once and verify no Build was added, then confirm Import. Import an unrelated homebrew ROM: New Game remains selected.
- [ ] Import a known No-Intro regional release, then search by another title in its family: "Pocket Monsters Crystal" finds Pokémon Crystal. Rename Game in Game Details, reopen the app, and verify the new title and the former-title search both work.
- [ ] In Settings > Library > Regions and Languages, verify USA, Europe, Japan is the initial region order and reorder both lists. Import Japan then USA releases of one family: review proposes the better title and Preferred mark. Cancel changes nothing; decline either proposal and Import keeps that choice; accept both and reopen the app to verify them. A lower-ranked release doesn't take Preferred, ties stay stable, and a title set with Rename Game never receives a replacement proposal. Changing the order alone leaves existing Games unchanged.
- [ ] Keep a protected Japan-titled Game holding a USA release under the default order: import never proposes replacing its title. Settings > Library > Suggest Names shows its current title, proposed USA title and release region above Build names; homebrew and Games already titled by their best release get no Game suggestion. Cancel changes nothing. Accept one title, edit another and skip a third, then Rename and relaunch: accepted titles keep the old title as an alias and allow later regional import proposals, edited titles stay protected, skipped Games stay unchanged, and every Preferred Build stays put. Existing Build name suggestions still accept, edit and skip as before. With neither kind to suggest, the empty state says Game titles and Build names look right.
- [ ] Keep regional releases of one family in separate Games. Settings > Library > Suggest Game Merges lists them. Close the review and verify nothing changed; reopen, choose a subset, survivor and title, and Merge. Reopen the app: selected Builds keep their identities, lineage, states and Save Profiles, the survivor keeps its artwork or receives available source artwork, and unselected Games stay separate. A group with duplicate images refuses the move before any Game is merged.
- [ ] Import an unknown ROM and choose Match Game. Search the library and No-Intro data, including a base ROM absent from the library, and mark it as a hack or another Build. Before Import, the library is unchanged; after Import and relaunch, the recorded base game remains visible and verification stays Unknown. Import the base later: review offers the Game and Base mark; cancel or decline leaves them alone, and confirming links the clean Base without replacing the hack's lineage. With several Games recording that base, choose the destination explicitly.
- [ ] Import a ROM with metadata tags, such as `Example (Europe) (En,Fr) (Rev A) [v1.10].gb`. Correct or clear Build Details in review. Reopen the app and confirm Technical Info shows the chosen values.
- [ ] Open a Build's Technical Info > Metadata Details and edit a field with a recorded offered value. Relaunch the app: the saved value remains, the source reads You, and the earlier offered value is kept.
- [ ] Open a Build's Technical Info and read the Header section: title, color support, cartridge type by name (a battery game reads such as "MBC5 + RAM + Battery"), ROM and RAM size, revision number, and header and global checksums reading Valid for an unmodified ROM. - [ ] Share a compatible Save Profile between Builds, then fork it and confirm divergence.

Relaunch the app and confirm each saved choice persists.
